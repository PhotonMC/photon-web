# Photon web design guideline

This page records what the home page (the waitlist, now at `/waitlist`) already does, so every
other page looks like the same product. When a page needs something this guide does not cover,
add it here in the same commit.

## Principles

- **Tactile, flat, hard-edged.** Thick borders and offset shadows with **no blur, ever**. Corners
  use the control radius (cards a little more), nothing glows, nothing gradients.
- **Monochrome first.** Ink on paper (light) or paper on ink (dark). Colour is only for state
  (`--ok`, `--bad`). There is no brand accent colour beyond ink.
- **Mono for meta, Figtree for voice.** Anything that labels or counts is mono; anything that
  speaks is Figtree.
- **One idea per screen.** Generous space, few elements, large type.

## Tokens

The source of truth is `design/tokens.json`. `app/tokens.css` and the client's
`photon-gui/src/tokens.rs` are generated by `scripts/gen-tokens.mjs`; never edit them by hand, and
a new token means regenerating and committing both repositories. Use the Tailwind names from
`app/globals.css`:

| Use | Class / variable |
| --- | --- |
| Page background | `bg-bg`, `--bg` |
| Text | `text-ink`; secondary text `text-muted` |
| Hairlines and dividers | `border-line` |
| Panels | `--card` (via `.card`) |
| Shadow colour | `--shadow` |
| State | `--ok`, `--bad` |
| Control radius | `--radius-ui` (`rounded-control`), cards `rounded-card` |

## Type

- **Figtree** (`font-sans`) for everything spoken. Display text is weight 800 with tight tracking.
  The wordmark (`.wordmark`) is the only text with a hard text-shadow.
- **JetBrains Mono** (`font-mono`) for numbers, status and labels.
- `.label-mono`: uppercase, `0.24em` tracking, muted. Use it for meta text such as "12 online",
  versions, section captions and navigation.
- Body copy: `text-muted`, `text-pretty`, comfortable line length (about 640px).
- Page title: `text-[32px]`, weight 800. Notice pages (`NoticePage`) use `text-[28px]`.

## Components (`app/globals.css`)

- `.card`: `--card` background, `2px` ink border, `rounded-card`, hard shadow (`6px 6px`).
- `.btn`: filled ink, `2px` ink border, 44px minimum height, bold. On hover it **presses into its
  shadow** (translates 3px and shrinks the shadow). Primary actions only; one per view.
- `.btn-outline`: the same on `--card`, for secondary actions.
- `.btn-icon`: 44px square, smaller shadow.
- `.field`: 56px tall inputs, 18px text (no iOS zoom), hard shadow.
- Footer: `border-t border-line`, `.label-mono`, items separated by ` ✦ `.

## Layout

- Page gutters: `px-5` on phones, `sm:px-10` from tablets. Content width: `max-w-[1100px]` for
  the game list and the header, `max-w-[960px]` for a game page, `max-w-[720px]` for settings and
  reading pages.
- Vertical rhythm: sections are `gap-6` or `gap-8`; hero blocks use `mt-10` to `mt-12`.
- Everything that is pressed is at least 44px high and wide.
- Focus is a `2px` ink outline with a `3px` offset (`:focus-visible`); do not remove it.

## Navigation bar (shared shell)

Every page except the waitlist sits in the shared shell: a header with the logo mark linking to
`/games`, the sections (Games, Avatar, Marketplace, Settings) as `.label-mono` links with the
current section underlined, and on the right the signed-in name or a Sign in link, then the theme
toggle. On phones the logo, Sign in and the theme toggle share the first row and the links sit on a row of
 their own beneath, with tighter tracking; they are never hidden behind a menu. The footer
repeats the home page's footer style.

## Game card

A tile for one game, used on the list: a `.card` with a 16:9 thumbnail area on top (the game's first
picture, or a flat `--line` placeholder with the first letter in display type), the name in Figtree
700, then `.label-mono` stats ("12 online · 1.21"). The whole card is one link. Hover presses it
like a button. Operator pictures always carry `referrerPolicy="no-referrer"` and are only `https`.

## Behaviour

- Dark mode is the `.dark` class on `<html>`, set before paint by the inline script and changed by
  `ThemeToggle`. Never use the media query directly.
- Respect `prefers-reduced-motion`: no animation beyond the logo pulse, and that stops too.
- Play is always a `POST` form, never a link (the origin check depends on it).
- Pages that are not built yet say so plainly ("Coming soon") and invent no items, prices or
  buttons.
